# エンジンの仕様

[マニュアル一覧](README.md) · [Rust API](rust-api.md) · [C API](c-api.md)

メジロエンジンは、1ストロークと直前の状態から、文字列・キー操作・次の状態を求めます。
Rustコアは `no_std` で、外部クレートへの依存やヒープ確保を必要としません。
物理キーの読み取り、同時押しの確定、IMEとの通信は[接続層](integration.md)が担当します。

## ストロークの表記

入力はASCII文字列です。大文字と小文字を区別します。

```text
[#] 左手 [-] 右手 [*]
各手 = 子音(STKNの順) + 母音(YIAUの順) + 追加音・助詞(ntkの順)
```

角括弧は省略可能な要素を表します。各グループ内では必要なキーだけを、この順序で並べます。
たとえば左手 `K` と `A` は `KA-`、左右の `k` は `k-k` です。
`#` は先頭、`*` は末尾に置きます。Ploverのハイフン省略形も受け取れますが、自作の接続層では左右の区切りを明示すると読みやすくなります。

空文字列、非ASCII、順序違反、重複キー、末尾の余分な文字はエラーです。
ストロークの構文が正しくても、変換規則で扱えない入力は `InvalidStroke` になります。
キー名と実際のキー位置の対応はキーマップ側で定義します。

## 片手モード

入力モードは `Both`（初期値）、`Left`、`Right` の3種類です。かな／ローマ字／JISかなの出力モードとは独立しています。
物理的な片側の全キーには記号キーも含めます。左側は `#` と `STKNYIAUntk`、右側は `STKNYIAUntk` と `*` です。

| ストローク | 動作 |
| --- | --- |
| `#STKNYIAUntk-` | 左手モードへ移行 |
| `-STKNYIAUntk*` | 右手モードへ移行 |
| `#STKNYIAUntk-STKNYIAUntk*` | 両手モードへ戻る |

同じ側の全押しはモードを維持します。切り替え打鍵は文字を出さず、文法分類・母音・保留促音を保持します。`Session` では切り替え自体をUndo履歴やマクロ出力に追加しません。
反対側のキーを含む入力は、その打鍵から通常の両手入力として処理し、両手モードへ戻ります。
片手略語の記号キーは左手モードでは左の `#`、右手モードでは右の `*` です。反対側の記号キーも両手入力への復帰として扱います。
エラーになった入力は確定されず、モードも変更しません。

基本かな・追加音・二重母音・マイナー母音・例外かなは両手版と同じ変換表を使います。
子音単体は五段、い段は上一段、え段は下一段の動詞を生成します。たとえば `K` は「く」、`KI` は「きる」、`KIA` は「ける」です。
右手モードでは同じ入力を `-K`、`-KI`、`-KIA` と表記します。通常の右手コマンドはこの間は適用しません。

以下の略語表記の `*` は使用する手の記号キーを指します。左手の `K*` は実際のストロークでは `#K-`、右手では `-K*` です。

`*` 付き入力は一般略語を優先します。右手一般略語、左手一般略語の順に既存の語彙を使い、`ST*` は「から」とします。
`K*`＝「この」、`S*`＝「その」、`KAU*`＝「こと」、`TAU*`＝「ところ」、`TKA*`＝「はなし」です。
専用動詞の `*`＝「する」、`KU*`＝「くる」、`TN*`＝「です」は一般略語より優先します。
残りの枠は両手版の左側だけで登録された片手動詞（`VERB_MAP` の `左-`）を共用します。未登録枠で一般動詞の生成規則にも当てはまらない略語はエラーです。
実行時辞書の `GeneralRight`・`GeneralLeft`・`Verb` の上書きも参照します。

| 親指 | 親指単独 | 一般略語＋`*` | 動詞活用 |
| --- | --- | --- | --- |
| `n` | Space | 、 | ない |
| `t` | 、 | に | た |
| `k` | 。 | の | ます |
| `tk` | ・ | で | ました |
| `nt` | ？ | と | なかった |
| `nk` | を | を | ません |
| `ntk` | Enter | は | て |

動詞活用は両手版の右側活用表を共用します。「です」の専用活用も通常版と同じで、`TNt*` は「でした」です。
`KAUntk*` は「ことは」、`ntk*` は「して」になります。親指なしの動詞は辞書形です。
母音・文法・促音・出力形式・記録は通常と同じ仕組みを使い、`Session` のUndoは現在の入力モードを維持します。

## 変換の流れ

1. ストロークを左右の子音・母音・追加音に分け、undo・マクロなどの制御要求を判定します。
2. コマンドを有効にしている場合は、登録されたコマンドを判定します。
3. ユーザー語、助詞、一般略語、動詞、左かな＋助詞、通常音節の順に規則を適用します。
4. 出力の文法分類を求め、選択した出力モードへ変換します。
5. 出力と次の状態を返します。

制御要求は分類した時点で返します。登録コマンドも専用の出力をそのまま返し、母音の更新と出力モード変換を通りません。
`include_commands = false` で省くのは登録コマンドの判定で、undo・マクロなどの制御要求は引き続き分類します。

`translate` はこの計算だけを行います。`Session::process` は計算結果を確定し、履歴とマクロも更新します。
同じ辞書候補を何度も調べる処理では `translate` を使います。

## 動詞の定義

登録動詞は `src/tables.rs` の `VERB_MAP` に、`("ストローク", &["語幹", "活用行"])` の形式で定義します。
活用行は子音のみなら五段、末尾が `i` なら上一段、`e` なら下一段です。
サ変は `sh`、カ変は `kh` とし、たとえば `["きに", "sh"]` で「気にする」、`["もって", "kh"]` で「持ってくる」を表します。ナ変は定義しません。
たとえば `("KA-KNA", &["かが", "m"])`、`("KA-SNI", &["かん", "zi"])`、`("KA-", &["かんが", "we"])` です。
左右の助詞キーから活用形と付属語を選び、共通の活用表で出力を組み立てます。登録動詞は `*` 付きで使います。

左だけのショートカットはその音から始まる動詞を選び、左右ありとの重複を許します。「ある・行く」と敬語動詞の一部は、活用行に加えて語幹を見て特殊活用を処理します。

登録順は語幹ではなく、ストロークをかなに変換したあいうえお順です。左手・右手の順に比較し、省略母音は初期値 `A` と右手への母音継承で補います。同じ読みならストローク文字列順です。

## 状態

| 状態 | 初期値 | 役割 |
| --- | --- | --- |
| 文法分類 `context` | `Unknown` | 次の助詞を選択するための直前の分類 |
| 母音 | `A` | 母音省略時の補完 |
| 入力モード `input_mode` | `Both` | 両手／左手／右手入力の選択 |
| 出力モード `mode` | `Kana` | かな／ローマ字／JISかな入力用の出力を選択 |
| 未出力の促音 | なし | 次の入力まで持ち越す「っ」 |

文法分類は `Unknown`、`Nominalizable`、`Incomplete`、`AttributiveNa`、`QuestionPredicate`、`Noun`、`Place`、`IndefiniteNoun`、`QuestionParticle` の9種類です。
通常のかな文字列の末尾から品詞を推測するのではなく、適用した規則が分類を設定します。
単独助詞は直前の確定した分類を参照し、同じストロークに語と助詞が含まれる場合はその語の分類を参照します。

母音の省略は左右と前の状態を参照して解決します。通常音節では左の明示母音を右へ引き継ぎ、左の母音が省略され右だけに母音がある場合は左にもその母音を使います。
両方が省略されていれば前の母音を使います。具体例は[母音の引き継ぎ](examples.md#母音の引き継ぎ)を参照してください。

子音が `STN` だけで母音がない手は、母音を補完せず「かななし」として扱います。追加音だけを出力するため、`STN-` は空、`STNtk-` は「っ」、`STNntk-` は「ー」です。末尾が `STNtk` の「っ」はローマ字・JISモードでもそのストロークで出力し、通常の促音のように次の子音を待ちません。[仕様例](examples.md#stn単体と追加音)も参照してください。

## 文字とキー操作

`Output` は `text`、`operations`、`context` を持ちます。
文字列はUTF-8です。キー操作は文字列とは別に保持し、`byte_offset` の位置に挿入して実行します。
同じ位置に複数の操作がある場合は、配列の順番に実行します。

たとえば `-TYI` の出力は、文字列 `（）` と、バイト位置6の `Left` です。
接続層は `（）` を出力した後、左矢印を1回送ります。操作位置は文字数や削除回数ではありません。

キー操作にはReturn、Space、Tab、Backspace、Delete、方向キー、Home/End、Shift付き移動、Shift/Ctrl付きReturn、Shift+0、IME ON/OFFがあります。`#-t` は `ImeOn`、`#-k` は `SelectAlternateSystem` → `ImeOff` の順に操作を返します。別システムの実装・登録がある場合だけ接続層で切り替え、なければ切り替えを何もせず完了させます。IME OFFは切り替えの有無にかかわらず実行します。接続層がQMKの `KC_LNG1/KC_LNG2`、またはPloverの `MEJIRO_IME:on/off` へ変換します。F13/F14のABI値は保持しますが、これらのストロークからは出力しません。
それぞれをPloverの操作やファームウェアのキーコードに対応付けます。

## 出力モード

| モード | 内容 | `KA-` の文字出力 |
| --- | --- | --- |
| `Kana` | かなを含むUTF-8文字列 | `か` |
| `Romaji` | ローマ字入力用の文字列 | `ka` |
| `Jis` | JISかな入力のキーに対応する文字列と操作 | `t` |

`Romaji` と `Jis` は入力形式の変換です。OSのIME設定を切り替える機能は接続層で扱います。
`Jis` の文字はキーを表し、たとえば「を」は `Shift0` 操作になります。
モードに応じて促音を持ち越し、後続入力と合わせて出力します。Return・Space・Tabの前では保留した促音を出力します。

`Session` では `set_typing_mode` で `Romaji` または `Jis` を選び、`#-n` で `Kana` と選んだモードを切り替えます。
初期の選択先は `Romaji` です。`set_typing_mode` だけでは、初期状態の `Kana` から切り替わりません。

## 履歴と取り消し

Rustでは `Session::<H>` の `H` が最大履歴数です。既定値およびC APIは20件です。
上限を超えると古い履歴から捨てます。`H = 0` では履歴を保持しません。直前出力の繰り返しは行わず、`-U` は後述の履歴なし動作になります。

出力後、接続層は `ticket` に対して実際に取り消せる削除単位を `acknowledge` で登録します。
最新の履歴に1回だけ登録でき、空の出力はエンジン側で0として登録済みになります。
未登録の履歴を取り消すと `Unacknowledged` となり、状態は変わりません。

`-U` は直前の出力前の文法・母音・促音を復元し、登録された削除単位を返します。
現在のモード選択は維持します。取り消しイベントの `output` は削除対象の説明であり、再送する文字列ではありません。
履歴がない場合もundoイベントを返し、接続先に2文字分の削除を要求します。この場合、文法分類・母音・促音はリセットし、出力モードとマクロは保持します。

Shift+0・Return・Space・Tab以外のキー操作を含む出力は、過去の履歴を切ります。
外部編集やIME確定などで取り消し単位の対応が失われたときは、接続層から `reset` を呼びます。
エンジンは外部アプリで起きた編集を自動検出しません。

`reset` は文法分類・母音・促音・履歴を初期化します。出力モード、記録済みマクロ、記録中の枠は保持します。
マクロを含めてすべて初期化するには、新しい `Session` を作ります。Cでは `session_init` を再実行します。

## 繰り返しとマクロ

| ストローク | 動作 |
| --- | --- |
| `#-` | 直前の解決済み出力を繰り返す |
| `#n*` または `#n-*` | `n` 枠の記録を開始／停止する |
| `#-*` | 最後に開始した記録中の枠を停止する |
| `#n` | `n` 枠を再生する |

マクロ枠は `n, t, k, nt, nk, tk, ntk` の7個です。表の `n` を他の枠名に置き換えて操作します。
記録開始時にその枠の前の内容を消し、複数の枠へ同時に記録できます。

繰り返しとマクロは、助詞選択と出力モード変換を済ませた文字・操作を保存します。
再生時に再変換しないため、記録後にモードを切り替えても保存した出力形式のまま再生します。
マクロ再生後の文法分類は `Unknown` です。undoはマクロの記録ログを巻き戻しません。

## 容量とエラー

| 対象 | 上限 |
| --- | --- |
| 1出力の文字列 | UTF-8で512バイト |
| 1出力のキー操作 | 8個 |
| 各マクロ枠 | 文字列512バイト、キー操作8個 |
| 履歴 | Rustで指定した `H` 件、Cでは20件 |

`Session` は履歴とマクロの固定領域を持つため、組み込み先ではサイズとスタック余裕を確認します。
具体的な必要量はRustの `size_of`、Cのサイズ照会APIで取得します。

| Rustのエラー | 意味 |
| --- | --- |
| `InvalidStroke` | 不正なストローク、または扱えない組み合わせ |
| `Capacity` | 出力やマクロの容量不足 |
| `InvalidState` | 不正な状態・モード指定・acknowledge |
| `Unacknowledged` | 削除単位の登録前に取り消しを要求した |

`Session::process` がエラーを返した場合、状態・履歴・記録内容を変更しません。
容量を超える文字列を黙って切り詰めることはありません。
出力先への送信は接続層が行うため、送信失敗の検出と履歴の無効化も接続層で扱います。
